# v8 scope — clean-room rebuild after v7 divergence discovery

**Written UTC:** 2026-07-13 15:15
**Trigger:** 2026-07-13 live/backtest divergence discovery. v7.1 filters shipped to backtest only; live ran v7.0-default with no per-session gates. Path Y honest DSR audit failed (n=25, CI [-$112, +$954]).
**Status:** Scope. Not implementation.

## Why v8 (not v7.2.3)

We could patch v7 further, but the underlying failure mode is structural:
- Filter definitions live in TWO places (backtest engine, live dispatcher) with no enforcement they stay in sync
- Tests exist for backtest logic; live dispatch has no coverage of filter behavior
- Position sizing, trade tracking, and evaluation each rebuilt the strategy semantics — 3 chances to drift
- Regime awareness is bolted-on (real yield analysis lives in ad-hoc scripts) rather than integrated

Any v7.x patch would have the same class of bug re-emerge. v8 is a rebuild that removes the class.

## v8 design principles

### P1 — single source of truth for filter logic

- **One module** (`src/strategy_engine.py`) defines each filter as a pure function
- Backtest engine, dispatcher, shadow tracker, and analysis scripts all import from this module
- Change one place → change everywhere. No config drift possible.

### P2 — filter definitions are testable in isolation

- Each filter is a pure function: `(bar_context, session_config) -> would_skip: bool | (would_skip, reason)`
- Unit tests cover boundary conditions per filter
- Golden-file tests over 20 historical trades ensure filter behavior is stable across code changes

### P3 — regime awareness is a first-class input

- Every filter and sizing decision takes a `RegimeContext` argument:
  ```python
  @dataclass
  class RegimeContext:
      real_yield_10y: float | None
      dxy: float | None
      tnx: float | None
      prior_day_range: float | None
      # ...
  ```
- Regime-conditional filters explicit, not inferred from ad-hoc scripts
- Backtest MUST be run with regime stratification baked in

### P4 — dispatch is a thin runner

- Dispatcher's job: fetch bars, build RegimeContext, call strategy_engine, dispatch alerts
- No strategy logic in dispatcher. No side channels. No local variables shadowing imports (per today's UnboundLocalError fix).

### P5 — decisions logged before actions taken

- Every strategy decision (take/skip, direction, geometry, sizing) is written to a decision log BEFORE any Telegram alert or state change
- Enables perfect audit — you can always answer "why did we do X at time T?"
- Shadow tracker becomes trivial: same code path, just skip the "alert + enter" side effects

### P6 — one strategy version per registry entry

- No more v7.1 hiding inside v7.2.1. Each ship is a versioned strategy_engine snapshot.
- Registry entries link to specific strategy_engine commits
- SPRT and DSR audits are per-strategy-version, unambiguously

## Rejected principles (not going to do)

- **Type checking + mypy** — overhead high, doesn't catch the class of bug we hit today (semantic drift between two implementations)
- **Backtesting framework rewrite** (backtrader/zipline) — not gaining leverage vs pandas-native; adds maintenance
- **Feature-flag proliferation** — every flag is a divergence risk. Ship simpler config, not more.

## v7 → v8 migration path

### Phase 8.1 (design) — 2 days
- Sketch `strategy_engine.py` API (filter registry, RegimeContext, decision protocol)
- Enumerate every filter currently in v7 codebase, mark KEEP/DROP/REVISE
- Design test harness

### Phase 8.2 (scaffold) — 2 days
- Empty `strategy_engine.py` module with all filter signatures
- Test infrastructure (pytest + golden files)
- Regime context builder

### Phase 8.3 (port) — 3 days
- Port v7.0-actual filter (LON's `or_vs_atr_max=2.0`) as filter #1
- Backtest engine calls strategy_engine
- Dispatcher calls strategy_engine
- Both trees run same code → divergence impossible

### Phase 8.4 (re-audit) — 1 day
- DSR audit on v7.0-actual under strategy_engine wrapper
- Should match Path Y audit (n=25, 52% win, CI [-$112, +$954])
- If numbers don't match: bug in port, fix before proceeding

### Phase 8.5 (v8 filter development) — variable
- New filter candidates in strategy_engine.py
- Shadow-log each candidate for 30 days
- Ship gates: n≥100 shadow AND DSR pass AND SPRT clean

### Timeline

- 8.1–8.4: **~1 week** if focused. Establishes clean v7.0-actual baseline.
- 8.5: **as long as it takes** — no filter ships without shadow validation.
- Public launch (07-30): **slips**. Realistic new target: 2026-08-15 or later.

## Risk register

- **Sunk cost:** v7 represents ~3 months of work. Rebuilding hurts.
- **Motivation loss:** rebuild during losing period is psychologically heavy. Real risk of abandonment.
- **New bugs:** any rewrite introduces new bugs. Mitigated by golden-file tests but not eliminated.
- **Timeline slippage:** 07-30 launch commitment moves. Public communication needed.
- **Wrong regime forever:** if we rebuild v8 during the ry≥2.2 regime, we may over-fit to it.

Path Y' (halt NY, LON+ASIA at half-size) is a lower-effort path that keeps v7 running while collecting data. If we're honest that DSR fails, Y' is trading with a strategy that shouldn't be deployed. That's a discipline choice.
